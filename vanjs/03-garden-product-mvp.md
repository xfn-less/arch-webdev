# Garden 产品思考与 MVP

这份文档记录当前对 Garden 的产品定位、最小实现和长期方向的判断。它的目的不是写功能清单，而是给后续开发一个稳定的产品北极星，避免继续想到一点做一点。

## 1. 产品定位

Garden 不是普通 memo app，也不是 Markdown 知识库、大纲工具或 AI 笔记工具。

它更像：

```txt
一个快速、私密、可组合的在线个人内容空间。
```

核心目标：

```txt
用统一的条目保存想法、链接、任务、资料和回看内容，
再通过搜索、查询、视图和轻量复习，把它们重新带回用户面前。
```

一句话：

```txt
Garden 帮你保存那些还没成体系、但不该消失的小想法。
```

英文方向：

```txt
Garden is a fast, private, composable space for everything you want to keep.
```

## 2. 为什么值得做

很多记录工具各有优点，但也各有负担：

```txt
Workflowy
在线、快速、结构清楚，但更偏大纲。

Org-mode
强大、可自动化、长期可靠，但对普通用户太硬核。

Anki
间隔重复成熟，但学习压力强，内容被卡片模型限制。

Obsidian / TiddlyWiki
自由、可塑、可本地掌控，但插件、文件、链接和配置心智较重。

微信收藏 / 浏览器书签 / 备忘录 / 聊天记录
入口分散，后续很难统一找回。
```

Garden 想解决的是：

```txt
我现在不想整理成文章或系统，
但也不想让这个想法、链接、任务、对话片段散落并消失。
```

它的卖点不是功能更多，而是：

```txt
统一入口
统一条目
快速记录
强搜索
低负担回看
可组合视图
在线可用
隐私和可掌控
细节上的人文关怀
```

## 3. 核心原则

### 3.1 统一条目

Garden 的核心对象只有一个：

```txt
item
```

普通记录、链接收藏、任务、复习内容、分享内容，本质都先是一条 item。

不要一开始拆成很多系统：

```txt
memo system
task system
bookmark system
review system
share system
```

而是：

```txt
同一种内容
不同属性
不同查询
不同视图
不同动作
```

### 3.2 查询就是组织

Garden 不强迫用户先建立复杂结构。

很多功能都可以由查询和视图表达：

```txt
#todo
包含链接
去年今日
今天创建
待回看
最近编辑
某个关键词
某组公开分享
```

标签不是独立系统，先从内容里的 `#tag` 开始。

### 3.3 AI 只辅助，不接管

AI 可以用于：

```txt
润色
压缩
提取关键词
改写标题
整理一条内容的表达
```

但不能替用户自动接管内容判断。

原则：

```txt
AI 给建议，用户确认后才写入。
```

这点很重要，因为用户最终信任的是自己的记录，而不是被 AI 自动加工过的内容库。

### 3.4 复习是温和回访

Garden 可以集成轻量间隔重复，但不要变成 Anki。

不要做成：

```txt
正面 / 背面
答题
评分
牌组压力
连续打卡焦虑
```

而是：

```txt
今天可以回看几条
这条现在还对你有用吗
稍后再看
保留
完成
不再提醒
```

核心感受是：

```txt
重新遇见自己的想法
```

不是考试。

### 3.5 人文关怀是产品壁垒

Garden 不应该用焦虑驱动用户。

细节方向：

```txt
空状态不催促用户生产内容
搜索不到时给出返回时间线的出口
删除可以撤销
保存有温和反馈
网络断开不吓人
导出入口清楚
隐私说明写人话
不做 streak 绑架
不靠复杂统计制造焦虑
```

## 4. 最小实现

当前最小实现不是完整 SaaS，而是一个可以每天使用的 Garden Lite。

目标只验证四件事：

```txt
我能不能持续把东西放进去？
我能不能快速找回来？
它能不能温和地把旧内容带回来？
它是否比微信收藏、备忘录、浏览器书签更统一？
```

### 4.1 MVP 功能

第一版最小功能：

```txt
1. 快速保存一条 item
2. 本地持久化
3. 时间线倒序显示
4. 自动识别链接
5. 全文搜索
6. #tag 查询
7. 今天回看
8. 轻量 review
9. 删除和撤销
10. 基础反馈：toast、tip、快捷键
11. 导出 JSON
```

当前 UI 先围绕查询和列表视图，不做单个条目详情页：

```txt
时间流视图
默认视图，按创建时间倒序展示 item。

搜索结果视图
输入 query 后直接展示匹配 item。

固定查询视图
例如全部、包含链接、#todo、待回看。
```

因为条目本身很短，所以详情页不是 MVP 必需品。核心体验应该是：

```txt
输入查询
得到一组条目
用不同视图呈现这组条目
```

### 4.2 暂不做

MVP 暂不做：

```txt
Markdown 编辑器
富文本编辑器
复杂文件夹
大纲层级
知识图谱
AI 自动生成笔记库
Anki 式正反面卡片
完整项目管理系统
社交网络
真正插件市场
账号系统
多人协作
复杂分享权限
自由桌面布局
```

注意：任务和分享不是永远不做。

更准确的边界是：

```txt
不做独立任务系统，但允许用户用 item + query 自己创造任务流。
不做社交网络，但以后可以做一个或多个 item 的只读分享链接。
```

### 4.3 数据模型

MVP 可以从这个模型开始：

```js
{
  id,
  content,
  createdAt,
  updatedAt,
  deletedAt,

  review: {
    enabled,
    dueAt,
    interval,
    lastReviewedAt
  }
}
```

暂时不需要独立存：

```txt
tags
links
tasks
```

这些可以先从 `content` 里解析。

例如：

```txt
#todo 明天继续看 Sortable onEnd
https://example.com 这篇文章值得回看
```

## 5. 最小开发顺序

按这个顺序推进，不跳：

```txt
阶段 1：整理 Garden 基础结构
- 统一 item 数据模型
- load/save
- add/delete
- 时间线倒序
- 基础样式

阶段 2：输入体验
- Ctrl+Enter 保存
- 空内容禁止保存
- 保存后清空
- toast 反馈
- 删除撤销

阶段 3：链接与时间
- linkifyjs 自动链接
- dayjs 格式化时间
- 今天/昨天/更早分组

阶段 4：搜索与查询
- 搜索框
- Fuse.js 全文搜索
- #tag 查询
- 固定查询：全部、链接、#todo、待回看

阶段 5：回看与轻复习
- 每条可以标记 remind me
- 今日回看视图
- Later / Keep / Done

阶段 6：导出与收尾
- JSON 导出
- 空状态
- 移动端可用
- build 验证
```

## 6. 可用小库

这些小库符合当前路线：

```txt
linkifyjs
自动识别链接。

dayjs
时间格式化、相对时间、按天分组。

Fuse.js
本地模糊搜索。

tippy.js
按钮提示、危险操作说明。

hotkeys-js
快捷键。

toastify-js
保存、删除、撤销等反馈。

idb-keyval
后续替代 localStorage，适合更多数据。
```

暂时不做 Markdown，所以不引入 `marked` / `DOMPurify`。

## 7. 插件化方向

长期方向可以插件化，但 MVP 不需要先实现真正插件系统。

可以先按 feature 边界写代码：

```txt
core
link
search
review
feedback
export
```

以后插件不应该创造新的主数据结构，而是围绕 item 增加：

```txt
属性
动作
视图
查询条件
渲染增强
```

可能的插件：

```txt
Link 插件
识别链接、抓标题、favicon、摘要。

Review 插件
轻量间隔重复、今天回看、去年今日。

Task 插件
#todo 查询、done 状态、轻提醒。

Share 插件
公开链接、密码、过期时间、只读页面。

AI Assist 插件
润色、压缩、提取关键词，用户确认后写入。

Dashboard 插件
手机桌面式格子、壁纸、固定查询。

Import 插件
导入书签、CSV、JSON 等。

Export 插件
导出 JSON、HTML、静态页面等。
```

## 8. 发行版方向

Garden 可以有不同场景版本：

```txt
Garden Lite
本地/单用户 MVP，验证体验。

Garden Core
开源基础版，自部署、本地优先、记录/搜索/导出。

Garden Cloud
SaaS 在线版，同步、备份、跨设备、隐私承诺。

Garden Share
偏公开分享、链接集、项目日志。

Garden Review
偏学习、回看、轻量间隔重复。

Garden Platform
插件、桌面面板、多版本发行、自部署生态。
```

当前只做：

```txt
Garden Lite
```

但设计时不要堵死后面的 Cloud / Share / Platform。

## 9. 和 SaaS 能力的关系

如果 Garden 能从概念做到可用、可发布、可迭代，它基本会覆盖很多商业产品的通用内核：

```txt
数据模型
CRUD
搜索
权限
同步
分享
插件/扩展
多视图
导入导出
用户体验
性能
部署
隐私
商业版本分层
```

很多 SaaS 的差别只是业务对象不同：

```txt
Garden 的对象是 item
CRM 的对象是 customer / lead
项目管理的对象是 task / project
Helpdesk 的对象是 ticket
Notion 的对象是 block / page
Airtable 的对象是 record / table
```

所以这个项目不仅是学 VanJS，也是在练一套完整产品工程能力。

## 10. 当前判断

下一步不要继续泛泛加库，也不要先做平台。

应该先做：

```txt
一个人能每天用的 Garden Lite。
```

最小闭环：

```txt
记录 -> 搜索 -> 链接 -> 回看 -> 轻复习 -> 导出
```

只要这个闭环成立，后续的在线同步、分享链接、Dashboard、插件化、SaaS 分层才有继续扩展的基础。
