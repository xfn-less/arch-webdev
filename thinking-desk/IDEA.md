# 思考桌：点子暂存

> 暂用目录名 thinking-desk，产品名未定。当前暂停讨论，不实施。
> 通用开发偏好见 ../WEB-DEVELOPMENT-PREFERENCES.md。

## 出发点

用户习惯用 A4 纸整理思路和想法，想做一个个人和小团体可用的简洁空间工具。
参考 Scrivener 同厂的 Scapple 的素净感，不追求 Excalidraw 或商业白板的功能规模。
目标是能忽视其存在的趁手工具，而非功能繁多的绘图软件。

## 用户已表达的方向

- 有限桌面，无限画布是负担。
- 不做手写，支持方便的文字输入，以及移动、组织文字块。
- 借鉴 Vim 的模式思想，不是照搬 Vim 全套按键：块内编辑与块间整理有明确区别。
- 纯键盘应能使用，也支持鼠标和手机触屏。
- 同一桌面始终横向呈现，跨设备保持相同的空间布局，帮助位置记忆。
- 允许整体等比缩放与平移。改变观察视野，不响应式重排内容。
- 布局只能由用户主动整理改变，不因屏幕大小而自动改变。
- 浏览器本地存储即可，支持导出；暂不需要后端或复杂同步。
- 用户希望后续从真实使用过程开始，逐层展开细节，不直接把建议当作已确认规格。

## 暂定技术方案

- VanJS + goober，浏览器 ESM，无前端构建优先。
- 普通 DOM 文字块，固定桌面坐标，统一缩放；暂不需要 Canvas 或完整白板引擎。
- IndexedDB 存桌面数据，idb 薄封装。
- JSON 导入导出，带格式版本；导入默认生成新桌面，不无提示覆盖原件。
- 设备自身的视野位置、倍率与内容数据分开保存。
- 本地数据可能因清理站点数据等丢失，需提示导出备份。

## 尚未确定，不能当作既定需求

- 桌面具体尺寸、比例：类似横向 A4 是建议，不是已确认规格。
- 单张还是多张桌面，以及切换、归档方式。
- 文字块的创建、宽度、高度、换行、重叠与层级行为。
- 模式切换规则、键位、空间导航、触屏手势。
- 是否支持连线、分组、格式、多人共享等；不要默认加入。
- 保存节奏、撤销边界、恢复机制及数据字段。

## 下一次从这里继续

先请用户描述一次真实的 A4 纸思考过程：是边写边分叉、先分散写再建立关系，还是写满后重新整理？
再逐层讨论桌面与块、编辑与整理、输入方式、保存恢复，最后落实实现。
