# Text Vault

一个先用于长期日常记录的纯文本系统。核心只有：条目、URL 搜索、按创建时间排列的列表。先把记录和找回做好，不预建多视图、插件或通用查询框架。Telegram 用户脚本是外围适配，不属于核心。

## 运行

需要 Node 22.5 或更新版本：

```sh
npm install
npm run dev
```

打开 <http://127.0.0.1:8787>，首次创建主密码。默认只监听本机，数据库为 `data/text-vault.sqlite`。

## 日常操作

- 页面是完整条目的平级列表，按创建时间从旧到新排列；修改不会改变顺序。
- 底部中间始终显示一行搜索框，旁边的 `+` 新增条目。搜索框不会创建记录。
- 点击正文进入编辑；点击编辑框外、Esc、Ctrl+S / Cmd+S 保存。编辑中禁用搜索和新增，防止草稿消失。
- 不在输入框中时，`j` / `k` 选择下一条 / 上一条，Enter 编辑所选条目。`/` 聚焦搜索，`o` 新增。
- 搜索框里按 Enter 或 Esc 离开输入框；在列表里按 Esc 清空搜索。
- 顶部细状态条：编辑为绿、保存中为灰、成功融入背景、失败为红。失败保留内存更改；Ctrl+S 可重试保存。
- 清空整条正文并保存会删除条目。删除标记沿用加密同步，历史版本仍保留在原来的版本存储中，不会因刷新恢复。
- 关闭或刷新页面时，未保存内容会触发离开提醒；浏览器崩溃可能丢失内存草稿。

没有日期标题、未来提醒、分隔区域或选区悬浮搜索。原来文本中的日期记号现在就是普通文字。

## URL 搜索

所有搜索都使用 `#q=`，可以收藏、分享同一保险库中的搜索地址：

```text
http://127.0.0.1:8787/index.html#q=服务器
```

搜索不区分大小写，对完整正文做子串匹配。`tgId: ...`、`#项目A` 等都只是你约定的普通文字。

| 写法 | 含义 |
| --- | --- |
| `上海 服务器` | 同时包含两个词 |
| `上海 AND 服务器` | 同上，显式写“与” |
| `上海 OR 香港` | 包含任意一个词 |
| `上海 服务器 OR 香港` | 包含“上海且服务器”，或者“香港” |
| `"new york"` | 包含整个短语，空格不拆词 |
| `"OR"` | 搜索文字 OR，而非操作符 |
| `^"tgId: @vv333"$` | 整行文字相等，忽略行首尾空白和大小写 |

整行查询单独使用；`^"..."$` 内是原样文字，不是正则表达式，正文开头和结尾也算行边界。

操作符只认大写 `AND` / `OR`。与的优先级高于或，不支持括号、NOT、正则或字段类型。短语内可用 `\"` 和 `\\` 表示引号和反斜杠。引号不完整或操作符缺少搜索词时显示提示，不会误当作空查询。

空查询显示全部条目。输入直接更新 URL；打开链接和浏览器前进后退会恢复对应查询。旧 URL 的排序参数不再影响列表。

## 批量替换

在同一个搜索框输入 `AAA->BBB`：预览全库正文中原样文字 AAA 的替换结果，按 Enter 才执行。箭头两边可有空格；只有 `AAA` 或 `AAA-` 时仍是正常搜索，完整输入 `->` 才切换到替换预览。区分大小写，不支持正则。正文里的标签行也一起参与替换。输入命令、打开命令 URL 都只预览，不自动执行。

- `AAA->` 预览删除匹配文字，按 Enter 执行；替换后正文为空的条目会删除，预览会标明数量。
- `"AAA -> BBB"` 搜索这段文字，不执行替换。
- 需要保留首尾空格、换行或文字内的箭头时，可用 JSON 字符串，如 `"a -> b" -> "新文字"`。
- 确认前再同步并检查版本；如果预览后条目已变，不覆盖它，而是提示重新核对。

## 文本链接

```text
相关资料：[[上海 服务器 OR 香港]]
外部资料：https://example.com
```

- `[[搜索]]` 在当前标签打开对应搜索 URL；Ctrl/Cmd 点击或中键使用浏览器原生新标签行为。
- `http://`、`https://` 和 `www.example.com` 自动变成外部链接，在新标签打开；`www.` 默认使用 HTTPS。
- 编辑时仍是原始纯文本，不引入 Markdown、HTML 或富文本编辑器。

## 只有正文

查看、编辑、搜索和批量替换都使用同一份完整文本，不解析 YAML 或自定义属性。可以自行约定：

```text
tgId: @vv333bb
tgTitle: 收藏
#项目A

正文
```

`---`、冒号、重复名称都只是文字，没有校验、特殊背景或隐藏字段。以后真有需要，再从正文派生属性和视图，不维护两份内容。

旧版本已保存的自定义属性在读取时转成正文开头的 `名称: 值`，下次编辑保存时写回；只做旧数据兼容，不改写现有正文中的 `---`。内部同步元数据仍保留，不作为用户属性显示。

## 数据和代码

Node + Hono + SQLite；前端使用原生 ES modules 和 VanJS，无构建步骤。正文只在已解锁浏览器中解密，后端保存加密对象。现有加密、版本校验、增量同步和跨标签解锁继续保留。

```text
src/server.js                    HTTP 路由和 SSE
src/db.js                        SQLite 事务、对象与版本
src/auth.js                      登录会话和 CSRF
web/js/app.js                    解锁和模块装配
web/js/repository.js             内存数据、版本和冲突保全
web/js/save.js / sync.js         保存和同步
web/js/core/query.js             与或及短语搜索
web/js/core/text-links.js        识别纯文本里的链接
web/js/core/batch-replace.js      替换命令、预览和版本检查
web/js/views/river.js            列表、单一编辑草稿、键盘操作
web/js/browser/query-location.js URL 查询读写
web/js/legacy-properties.js      旧属性转正文的读取兼容
```

历史设计文档在 `docs/superpowers/`，用于保留决策背景，不代表需要补完其中的 workspace、视图注册器等架构。当前范围以本 README 和现有实现为准。

运行纯函数与数据逻辑测试：`npm test`。

## 局域网 HTTPS

浏览器加密 API 要求安全上下文；本机 localhost 可用 HTTP，局域网访问需 HTTPS。已有 Caddy 配置：

```sh
HOST=127.0.0.1 npm run dev
caddy run --config deploy/Caddyfile.lan
```

配置中示例地址为 <https://192.168.1.136:8443>；请按实际 IP 调整，并在设备上信任 Caddy 本地根证书 `~/.local/share/caddy/pki/authorities/local/root.crt`。

## 外围：Telegram 群便签

安装 `userscripts/telegram-search.user.js` 后，刷新 Telegram 和已解锁的 Text Vault。当前适配搜索完整一行 `^"tgId: <Telegram URL 标识>"$`，例如 `^"tgId: @vv333bb"$`，复用同一个全文搜索，不会把 `@vv333` 和 `@vv333bb` 混在一起；不要求上下留空白行。唯一命中就显示便签；多个命中自动打开对应搜索页，每次进入该聊天只跳一次；无结果可直接编辑新建，预填两行普通正文 `tgId: 标识`、`tgTitle: 首次群名`，不加 `---`，也不存为属性。两行只是你约定的文字，可以自由修改；保存后不自动补回或改名。旧属性在读取时转成普通正文，仍能命中。

脚本复用已解锁页面读写便签，保留该标签页即可。未打开聊天时的“全部群便签”只是指向 `#q=tgId` 的链接。面板保留原地编辑、收起及错误提示；点击正文时光标落到点击处，链接直接打开网页，不进入编辑。清空正文保存同样删除。未保存草稿按聊天暂存在页面内存。

脚本管理器暂存跨页请求/响应，正常接收后清理；密码和密钥不交给 Telegram。更换 Text Vault 地址使用脚本菜单，同时调整 `@match`。如果遇到旧桥接提示，先保存网页草稿，关闭其他旧标签，再刷新并解锁一个 Text Vault 页面。
