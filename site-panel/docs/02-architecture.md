# 02 技术与可靠性设计

## 1. 最终通信结构

主控：单 Go net/http 服务、SQLite、站点目录；VanJS ESM 与原生 CSS，同源 API。开发读取磁盘资源，正式 embed，无需前端构建。

节点：宿主机 Nginx、小型 Go 执行器、systemd。本地不常驻 Agent，无节点 HTTP API、令牌注册、回连或公网管理端口。所有管理通信由主控通过 SSH/SFTP 发起。

浏览器轮询主控任务 API；主控在同一次操作内复用 SSH 连接，按需查询节点，全局连接数受限。跨请求连接池以后按实际需要增加，不作为第一版前置条件。关闭页面清理浏览器轮询，不取消已提交任务。主控停机后节点任务继续；主控重启按持久化任务 ID 查询结果。

单个 SSH 连接失败可重连，但重连必须重新验证主机指纹。所有连接、命令、输出和传输设合理上限；不能无限占用连接池。

## 2. SSH 安装

1. 主控保存连接资料，密码应用层 AEAD 加密，密钥独立于数据库配置。
2. 首次读取 SSH 指纹，用户确认；安装连接核对同一指纹，变更拒绝。
3. 只读检查 Debian 12/x86_64、root 权限、磁盘、时钟、包管理器和已有服务。
4. 遇到宝塔、非受管 Nginx/目录冲突等停止，不接管未知业务。
5. 安装经测试来源的 Nginx；通过 SFTP 上传校验后的执行器、固定脚本和 systemd 模板 unit。
6. 建立 root 受限目录，检查执行器版本与 JSON status 输出；成功后显示已安装。

重复安装先检查管理标记，不重复追加配置，不自动升级系统或清空业务。apt 被占用时有限等待，不删除锁；安装中断明确记录失败阶段，检查状态再重试。

SSH 密码不出现在命令行、日志、JSON 状态和错误响应里。AEAD 密钥不能与密文一起存数据库，不写进仓库；首次在受限文件中自动生成，也可用启动参数指定独立路径。已有数据库缺失密钥时拒绝静默替换；密钥丢失会使已保存密码无法解密，需离线备份。

第一版 root SSH 是受信任高权限入口，并非隔离沙箱；后续可改受限用户/sudo，但不作为首个闭环前置条件。

## 3. 执行器接口

固定子命令示意，不代表已有可用命令：

- status：版本、Nginx 状态、任务摘要、采集时间，输出 JSON。
- submit <task-id>：从受控任务目录读取请求，验证后提交给 systemd。
- run <task-id>：由 systemd 调用，持锁执行固定类型任务。
- task-status <task-id>：读取持久化结果并核对 systemd 状态，输出 JSON。

任务 ID 仅允许固定格式，不允许用户把路径/shell 片段拼进 SSH 命令。复杂参数通过 SFTP 写入请求文件，不用字符串拼 shell。命令输出是结构化数据，日志单独存且限长脱敏。

无需 Unix Socket 常驻进程，也不做通用命令执行。部署、配置、文件和证书是明确的 Go 函数与 switch 分派，安装脚本只是固定实现细节。

## 4. 任务提交与断线恢复

主控先持久化任务 ID、节点、类型、输入摘要，再上传只读任务输入至任务专属目录。SFTP 上传先写临时文件，校验后 rename，最后发布完整请求。

submit 验证请求，使用固定 systemd 模板 unit 按任务 ID 启动。返回只代表提交被接受，不代表部署完成。若 SSH 响应丢失，先按同一 ID 查询/重试提交，不生成新任务重复操作。

systemd 按任务启动独立进程，进程不依赖 SSH 会话；服务禁止盲目 Restart=always 重做部署。状态文件原子替换，关键阶段同步到磁盘。整个节点管理操作使用内核文件锁串行执行；主控也按节点排队，不同时铺开大量等待进程。

任务状态：queued、running、succeeded、failed、needs_attention。连接状态另算；SSH 不可达不是任务 failed。状态中包含阶段、时间、输入摘要、错误码和脱敏说明。

节点任务目录保留完成结果一段明确期限；主控也保留结果。主控未取得结果前不能随意清掉远端记录。清理不删除活跃任务和当前站点数据。

服务器重启与 SSH 断线不同：运行中任务进程会终止。systemd 不保证自动恢复操作。下次查询/提交先识别未完成记录，检查文件/配置/服务实际状态；能明确恢复才恢复，含糊时 needs_attention。不无限重试安装或破坏性删除，不承诺恰好执行一次。

新 SSH 请求不能以超时为由强杀正在安装软件的进程。操作超时按类型处理，apt 中断先检查包管理器状态。

## 5. 状态查询

节点列表按需/低频查询，站点页面显示最后采集时间。正在执行的任务每几秒轮询直到终态；任务完成停止高频查询。

查询结果例：

```json
{"task_id":"固定格式ID","status":"running","step":"check_nginx","observed_at":"UTC时间"}
```

区分：SSH 不可达、执行器不可用、Nginx 未运行、任务失败。systemd 进程结束而没有最终结果文件时属于待核实，不可认定成功。

证书、磁盘、服务状态可以按页面需要查询，不在第一版扩展全天候监控告警。仅本机检查不能证明公网 DNS/防火墙和香港后端业务正确。

## 6. 文件与配置应用

主控冻结站点输入，生成清单和摘要；同步期间锁定该站点编辑，避免同一任务混入新内容。节点先下载/接收至同文件系统准备目录，检查路径、文件类型、数量、大小和摘要。未完成不影响 current。

使用受控 current 链接指向完整目录；用户内容中不支持任意符号链接。删除来自已确认的清单差异。大文件流式传输，断点续传可后置，不能把半文件当成功。

旧目录短暂保留用于本次失败恢复和在途请求，不无限存历史。空间检查覆盖新旧和临时数据；即使预检查通过也要处理运行中磁盘满。

Nginx 使用同一实际二进制检查包含全部站点的候选配置树。应用顺序：文件准备 → 候选配置/证书检查 → 文件切换 → 配置替换与 reload → 本机访问验证。各步骤记录恢复所需信息。

文件与配置没有跨资源原子提交保证。失败恢复旧配置/目录，记录恢复是否成功；恢复失败明确 needs_attention。不能只看 reload 退出码就宣布网站正常。

Nginx 只 reload，不每次 restart；检查连接和旧 worker，不能粗暴杀掉长下载。Vue 缓存旧资源问题由保留资源/缓存策略处理，目录切换不承诺客户端零错误。

原文 Nginx 编辑是高权限能力：限制站点级语法和允许路径，不随意 include/写系统文件。不能用几条字符串黑名单声称已安全沙箱化，超出支持范围明确报错。

## 7. SSL

后续选择成熟 ACME 工具/库，HTTP-01 需公网验证条件；先测试环境再正式签发。

续期由节点 systemd timer 独立执行，和配置应用共享互斥机制，不能同时覆盖配置。完成后本地保存证书与结果，主控连接时采集并安全取回。普通文件同步不触碰证书存储。

主控保存最新已采集证书，不承诺离线时也有节点最新续期副本。验证匹配、覆盖域名、链与有效期后入库；旧状态不得覆盖较新证书。私钥加密存储、权限收紧，不经普通文件 API 暴露。

换 IP 可恢复相同域名的有效证书；新域名不覆盖则重新申请。DNS、CA 限流、网络、过期等外部问题不由执行器保证成功。

## 8. 最小数据与目录

主控 SQLite：账号/会话、节点连接资料/固定指纹、站点/配置、证书元数据、任务输入摘要与结果。大文件在磁盘，不占数据库。任务和编辑摘要用于一致性判断，不是历史版本平台。

节点：执行器二进制、固定脚本/unit、受管站点根目录、证书专用目录、受限任务请求/结果/日志目录。无独立数据库服务器；任务记录用规范化 JSON 文件和原子写入即可。

主控使用具体 SQL、事务、外键和适当 busy timeout；不能把网络传输放在长数据库事务里。

安全底线：本地回环监听、会话/CSRF/限速、SSH 指纹固定、密码加密、路径边界、压缩包限额、固定任务、输出脱敏。文件名和错误内容不可直接 innerHTML 渲染。

正式使用前备份主控数据库一致性快照、站点目录、证书和独立加密密钥，实际演练恢复。不能仅复制运行中的 SQLite 主文件就称完整备份。

## 9. 故障边界

| 情况 | 预期 |
|---|---|
| 本地主控退出/Arch 休眠 | 已启动远端任务、Nginx、续期继续；重新打开查询 |
| SSH 断开/响应丢失 | 结果未知，按同一任务 ID 查，不盲目重复 |
| 节点重启 | Nginx 本地启动，未完成任务需核查恢复 |
| 传输失败/磁盘满 | 不启用不完整内容，保留旧站 |
| 配置错误 | 拒绝加载 |
| 节点整机丢失 | 从主控部署到新节点，用户切 DNS |
| 主控丢失 | 依赖独立备份，节点副本不是完整主控备份 |
