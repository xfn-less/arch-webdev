# 当前 SSL 与界面约定

## 界面以用户草图为准

用户明确不喜欢流行仪表盘风格。当前布局固定为：

- 左侧：IP + 备注列表，添加节点/刷新。
- 右上：当前节点站点表，列出名称、域名、SSL 剩余天数、Nginx 配置、打开文件夹、部署、日志。
- 右下：当前操作区，显示文件树/多标签 Ace、可编辑 Nginx 原文、SSL，或当前节点任务表 + 直接日志输出。域名端口在站点行编辑，不再放重复的信息页。
- 底部：一行终端式状态栏，保留任务/日志入口与实际操作结果，不再使用折叠日志抽屉。

依草图与最新参考：左侧节点栏；右上站点区（顶栏工具 + 站点表合为一块）；右下操作区。右区浅灰底、10px 间距和独立边框把三块分开。Lucide 图标、细分隔线、方形按钮。不要重新加入品牌横幅、统计卡片、圆角阴影、渐变、英文装饰标题、流程说明图或人为大留白。

前端仍然是无构建 VanJS、普通 ESM、原生 CSS、本地 Ace 和按需选取的 Lucide ESM。没有新增前端框架或运行服务。

任务记录在后端按当前节点过滤后取最近 50 条；只轮询该节点。切换节点清空旧任务和日志、取消旧日志请求并拒绝迟到响应。站点行“日志”直接打开该站最近任务；任务表名称可直接点击查看输出，返回工作区保留原编辑器和草稿。

## SSL 支持范围

已支持具体域名的 Let's Encrypt HTTP-01，测试签发、正式签发/复用有效证书、启用 HTTPS、独立续期、主控加密备份。**泛 DNS 解析不是通配符证书**；`*.xfnss.top` 泛解析可让 `dl.xfnss.top` 等具体域名解析到节点，但申请 `*.xfnss.top` 证书需要 DNS-01，目前没有接 DNS API。

要求：

1. 站点文件已部署，根目录有 index.html。
2. DNS 指向节点公网 IP。当前预检查使用节点自身解析并检查记录中包含管理 IP；CDN/私网管理入口等不同拓扑尚未适配。
3. 80 和 443 对公网开放，CAA 等记录允许签发。IPv6 错误记录也可能导致验证失败；不自动修改 DNS、防火墙或云安全组。
4. 在面板确认 Let's Encrypt 服务条款。邮箱可选，不填则不提供 CA 邮件通知。

操作：站点行点击 SSL → 填具体域名 → 同意条款 → 可先勾选测试签发 → 提交。任务在节点 systemd 中执行，不依赖浏览器或主控一直在线。

## 执行与失败保护

- Agent-free SSH 方式不变。节点执行器新增固定 ssl 操作、certificate-export 和 renew 子命令；不接受任意 shell。
- DNS 检查、Certbot 安装、验证路由、CA 请求、证书匹配/信任链、Nginx 检查、加载、实际 TLS/SNI 检查按阶段记录。
- Certbot 仅在节点缺少客户端时从受管 Debian 官方源安装。自有 ACME 数据位于 `/var/lib/site-panel/acme`，测试数据位于 `acme-staging`，互不覆盖。
- 验证目录 `/srv/site-panel/acme/.well-known/acme-challenge/` 独立于网页同步目录，不被上传页面覆盖。
- 测试证书只验证，不启用、不存为生产证书。测试任务结束恢复原配置，包括原 HTTPS。
- 普通部署检测节点已有证书，继续生成 HTTPS 配置，不因主控的旧状态静默取消 HTTPS。
- 自定义 HTTP 端口保留。例如原 :18080 继续提供 HTTP；域名的 :80 负责验证和跳转 HTTPS，:443 提供网站。HTTP 本身就是 80 的站点暂不强制跳转，避免改变已有 HTTP 使用方式。
- 失败恢复旧 Nginx 配置。修改已有证书域名时，还保存/恢复 Certbot live 链接及 renewal 设置，避免“旧域名配置 + 新证书”不匹配。恢复资料位于任务目录；突发断电/进程强杀仍需人工核实，不承诺自动完整回滚。
- 不强制每次签发：有效且未临期的同域名证书由 Certbot 复用，避免消耗正式额度。

## 续期与主控备份

- 自有 `site-panel-cert-renew.timer` 每日两次调度，带随机延迟；服务持节点操作锁，运行 Certbot renew，检查并 reload Nginx。
- 新安装的 Certbot 默认 timer 会关闭，避免无关的 `/etc/letsencrypt` 定时器；预先存在的客户端/其他站点 timer 不接管。
- 主控离线不影响节点续期。主控证书副本并非离线实时更新，SSL 页显示最后备份时间，需要点击“从节点同步证书”；正式 SSL 任务成功后自动同步。
- 通过 SSH 读取证书和私钥，只向浏览器返回公开元数据。私钥不进普通文件接口、日志或 HTTP 响应。
- 数据库 certificates 表中，完整证书及私钥用主控 AEAD 密钥加密存储；公开信息单独保存供列表显示。备份时仍须保存 master.key。
- SSL 任务已成功但主控取回失败时，标为待核实/ssl_sync，不能谎称证书申请失败或备份成功；可以重试同步。
- 一键换机恢复证书尚未接入；目前完成的是备份与取回，不应将有备份等同于恢复流程已验收。

## DNS 检查

部署前用公共 DNS（DoH / 1.1.1.1）核对域名 A 记录是否指向节点 IP，不走本机 stub/Clash Fake-IP。不符时警告并可强制继续；面板不改 DNS。

## 当前真实验证

- 域名：`panel-test.xfnss.top`，公网 DNS 为 `103.149.201.31`。
- 原站点 ID 与文件保持不变，只为原 HTTP 站点增加此域名和 HTTPS。
- 初次测试签发成功，初次正式签发成功，外部 TLSv1.3 验证通过。
- 正式证书到期：2027-01-18 12:31:51 UTC，签发者 Let's Encrypt YE1。
- Certbot `renew --dry-run` 成功；独立 systemd 续期服务实际执行结果 success / 0。
- 控制端 API → SSH → 节点的测试签发集成测试通过；过程中曾有短暂 SSH EOF，查询按未知处理，没有据此重跑正式签发。
- 另外验证了复用有效生产证书的任务，不强制重复签发。
- 原 `http://103.149.201.31:18080/` 保留，HTTPS 地址 `https://panel-test.xfnss.top/`。
- 已把证书、域名、任务记录导入真实主控，私钥加密保存；没有改原账号、会话或站点文件。

开发期工具 `cmd/import-certificate` 仅为离线维护：停主控后导入通过已验证 SSH 获取的受限 JSON 文件；不是无认证 Web 导入接口。`scripts/ssl-smoke.py` 会修改指定测试站的 Nginx/ACME 状态，必须显式 `--agree-terms`，仅用于当前测试环境。
